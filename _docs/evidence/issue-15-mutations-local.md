# Issue 15 mutation implementation evidence

The Planning mutation feature provides a durable, owner-bound preview and an explicit confirmation boundary for completion, cancellation, and rescheduling. `preview_mutation` is read-only with respect to plan state and stores a 24-hour preview. `confirm_mutation` reloads and locks the current owner preferences, preview, Planning targets, recurrence state, then checks Billing and consumes a one-time Telegram proof in the caller-owned unit of work. It writes an idempotent receipt with the mutation.

Single-occurrence completion and cancellation preserve the occurrence identity and history while incrementing its version and emitting `planning.occurrence_completed` or `planning.occurrence_cancelled` with the occurrence UUID as aggregate ID. Rescheduling uses the existing recurrence-exception API for series changes. The preview lists the selected schedule projection; confirming a future exception preserves the remaining recurrence count and already-completed history.

Future cancellation binds the series version and the exact generated open occurrence IDs, recurrence keys, versions, and dates into the preview digest. Confirmation locks the series, selected links, and occurrence rows, then atomically cancels that selected future set and stops further generation. Completed/past history and occurrence IDs remain intact. It emits one versioned occurrence-cancelled event per changed occurrence plus `planning.series_stopped`. A failed multirow transaction leaves the preview and its token usable for retry.

The Telegram adapter renders the proposed action and schedule/reminder effects, then issues compact one-time callbacks with a 15-minute lifetime. The persisted mutation preview remains valid for up to 24 hours; the application still rejects a stale, expired, foreign-owner, changed-version, or already-started reschedule confirmation.

Validation used the assigned disposable PostgreSQL fixture (port 51017, `pin_issue15_` database, guarded temporary data directory). `tests/test_planning_mutations_postgres.py` passed 5/5, covering read-only previews, idempotent confirmation, no reopening, reapproval of stored reminders after a preferences-version change, stale and foreign-owner rejection, expired proof, started-occurrence reschedule rejection, two-week reanchoring with unchanged remaining count/history, future cancellation, and rollback/retry after an injected mid-batch failure. Focused Ruff checks passed. Telegram command/callback routing, facade exports, and home-zone preference handoff are shared integration work and are not claimed by this local evidence.

The home-zone handoff adds a durable 24-hour, owner/profile-version-bound preview and an explicit one-time proof boundary. The preview serializes the complete bounded set of future open timed occurrences and active recurrence definitions, with before/after event schedules, saved reminder offsets, candidate quiet-hour policy, reminder due/omission/quiet-adjustment effects, exact selected occurrence/series IDs and versions, and unresolved legacy reminder semantics. “Keep” can select no event schedules and preserves event zones and local wall times; only explicitly selected occurrences or series are reinterpreted in the candidate home zone. Profile save, future occurrence requalification, recurrence policy refresh, invalidation events, and preview confirmation share the caller’s unit of work. Past/completed records remain untouched; active series retain their anchor, rule, total count, end date, sequence, stable IDs, and generated history. Oversized previews reject without truncating their scope, and missing legacy reminder semantics require an explicit offset choice.

The dedicated guarded zone fixture is `pin_issue15_zone_worker_20261014_f83c` on port 51017 and the assigned disposable PostgreSQL data directory. `tests/test_home_zone_changes_postgres.py` passed 6/6, covering read-only preview plus Keep/reinterpret confirmation, a chosen active series with stable recurrence metadata and preserved completed history, stale target and foreign-owner proof rejection, rollback of the profile save when persistence rejects, empty Keep selection, and DST-gap rejection. Focused Ruff checks and `python -m pin.architecture` passed. The root-owned Telegram routing and Notifications extensions are wired in the shared tree; this local evidence covers the feature coordinator/store and does not claim end-to-end onboarding/profile callback smoke coverage.
