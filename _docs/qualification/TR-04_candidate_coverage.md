## Approved script pairing; audio still absent

Each candidate has one RU and one EN script aligned by `parallel_case_id` (`PAIR-001` through `PAIR-100`). For each language, `pair_id` identifies its script. The manifest has four records per parallel case: RU text, RU voice, EN text and EN voice. Within each language, text and voice rows repeat the exact same `input_text`, reference instant, home zone, category and expected plan. The owner approved this reference-set composition and script pairing. It does not establish real-world representativeness or allow text results to substitute for voice evidence.

For immutable provenance, text rows retain the original `draft_status: "text_candidate"` generation label; the linked approval record supersedes their script/reference approval state. Voice rows use `draft_status: "awaiting_real_audio"`; their `input_text` is only the intended reference utterance and `audio_artifact` is `null`. There is no synthetic or real audio in this artifact. A future authorized voice evaluation must attach eligible original audio recordings and score the result from the original recording, not treat the reference text or a transcript-only check as proof.

Each JSONL record has the same top-level fields: `id`, `pair_id`, `parallel_case_id`, `language`, `channel`, `draft_status`, `input_text`, `reference_instant_utc`, `home_zone`, `case_category`, `expected_plan`, and `audio_artifact`. `expected_plan` contains the language-specific intended title, plan kind, `start_delay_from_receipt_seconds`, local start and UTC instant, optional end and duration, resolved reminder values where targeted, `recurrence_rule`, `recurrence_reminder_offsets`, and `expected_occurrences`. The delay is non-null only for `elapsed_from_receipt`; its start instant is exactly the declared message-receipt reference plus that elapsed duration. It must not be replaced with processing or worker-start time. These cases use selected synthetic reference instants near ordinary hours, local midnight, month-end and year-end. For nonrecurring cases, recurrence fields are `null`/empty; for recurring cases, the rule and complete finite projection are populated. An untargeted inherited reminder is `null`, not a claim that the account has no reminder defaults. Other cases use their declared reference instant as context for dates. The home zone is `Asia/Qyzylorda`; explicit event zones are stored per plan. All voice artifact references remain null.
